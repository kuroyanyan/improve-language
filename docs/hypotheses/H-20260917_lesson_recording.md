# 仮説（H）
録音の開始を「レッスン中に開いている画面（カンペ）」に置き、相手（トレーナー）の声も一緒に録れば、レッスンの記録に文字起こしと AI フィードバックが付くのが普通になり、LOOP.md の成果指標のうち質問カバー率と往復比が実際に測れるようになる。
着想: 2026-09-17、黒川さん「（録音を始める）動線がないと、終わってからじゃないと記録ボタンをそもそも押さない」「せっかく録音機能があるのに、録音ができなかったのがめっちゃもったいなかった」「Notion AI のように相手の音声を取得して文字起こしできるように」。
それまでの録音開始ボタンは記録タブ（レッスン後に開く画面）にしか無く、マイクだけを録るので、イヤホンで受けるとトレーナーの声が入らなかった。

# 変更
- カンペ画面の上に「● 録音してレッスンを始める」。共有する画面の選択で MyStage のタブを選ぶと、タブの音（相手）とマイク（自分）を1本に混ぜて録る。共有しなかったとき・タブの音声が付いていないときは自分の声だけを録り、そう表示する
- 「レッスンが終わった → 記録する」（または同じボタン）で録音を止めて記録へ。記録タブの録音ボタンと「音声を保存」は外す（音声は保存しない。G8）
- 共有したタブが録音中に一度も鳴らなかったら（違うタブを選んだなど）、自分の声だけとして扱い、そう表示する
- 文字起こしは10分ごとに区切って送る（OpenAI の文字起こしは約23分を超える音声を受け付けないと報告されているため）
- AI に相手の声が入っているかを伝え、入っていなければトレーナーの質問を推測で埋めさせない
- 宣言ピースの回収: AI の判定で回収ボタンを先に押さない。本人が押し、AI の判定は `declared[].ai` に別に残す（H-20260915_piece_declare_recover の交絡欄「自己申告と AI の突き合わせ」を実際にできるようにするため）

# 分解
- H0: 操作チェック — 記録（sessions）に AI フィードバックが付いている。
- H1: 相手の声が入っている — 録音から作った AI フィードバックで、トレーナーの質問が数えられている。

# 交絡・バイアス
- 貼り付けた文字起こし（audio なし）は H1 の分母から外す。
- 宣言ピースの回収判定の作りを同時に変える（AI が先に押す → 本人が押す）。H-20260915_piece_declare_recover の H1-1 は従来どおり自己申告（`declared[].ok`）で判定し、`declared[].ai` との乖離を同ファイルの交絡欄の手順で確認する。
- 導入直後の目新しさ。3週の合計で判定し、初週だけでは判定しない。
- ブラウザ依存: タブの音は Chrome / Edge で共有できる（Safari は不可）。

# 外れた場合の解釈候補
- H0 不成立 → 押す場所ではなく、共有の手順（タブを選ぶ）が摩擦。自分の声だけで始められる既定に戻すか、手順を減らす。
- H0 成立・H1 不成立 → 共有の選び方を間違えやすい（「タブの音声も共有する」の付け忘れなど）。表示を直す。
