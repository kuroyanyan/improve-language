# Bizmates Log 改善ループ — 目的・指標・ガードレール

このファイルは、週1で走る改善ループ（claude.ai のクラウドルーティン）と、このリポジトリを触るすべての Claude セッションが従う規約。
**変更ゼロが既定。** ここに書いた目的と指標だけが、変更の根拠になる。

## 0. 目的（変えない）

黒川さんが **実戦で、自分の話を英語で言えるようになり、生活が豊かになること**。

- レッスンは練習、本番はフリートークとレッスン外。
- 内容は自分主体（自己開示）、形は相手主体（簡単な言葉で、相手の負荷を下げる。「大山スタイル」）。自己開示が相手の開示を引き出す構造を守るため、ピースには必ず投げ返しの質問を付ける。
- 学習分数・連続日数・カード枚数・改善回数・コミット数は **目的ではない**。

直近の実戦は 2026年12月のホノルル。長期は「世界のどこでも仕事ができる英語」。

## 3. 想定ペースと上方修正（G11）

進行中の仮説の判定基準は動かさない。**次のハードルを上げる規則だけを先に固定**しておき、早期達成や天井への張り付きを検知したら次段へ進む。遅い場合に基準を下げる規則は置かない（遅い理由の診断だけをする）。

| 指標 | 想定ペース | 上方修正の引き金 | 上げ方 |
|---|---|---|---|
| 言えるピース数 | 週2〜3個の卒業 | 3週連続で想定の1.5倍 | 卒業条件を「別の質問に対して3回」へ。30秒版を必須に |
| 宣言→回収率 | 70% | 3週連続 90% 以上 | 宣言を1日2ピースに。片方は「最近考えていること」系 |
| 質問カバー率 | 3ヶ月で 70% | 90% 到達 | 分母を「聞かれそうな質問」の拡張リストへ |
| 質問の往復比 | 0.5 → 1.0 | 1.0 到達 | 投げ返しを短答型から開いた問いへ |
| 60秒サンプル | 語数/分 +20%（3ヶ月） | 判定日前に基準到達 | 90秒に延長。お題に「最近考えを変えたこと」を追加 |

## 4. ガードレール（ループ自身に課す。毎回の報告で全項目を自己監査する）

| # | ルール |
|---|---|
| G0 | 目的は §0。学習分数・連続日数・カード枚数・改善回数・コミット数は目的でない |
| G1 | 変更ゼロが既定。1サイクル1変更。検証中の仮説があるうちは新しい変更を出さない |
| G2 | 時間予算は1日6分（記録30秒＋予習5分）、月1回3分。超える変更は効果見込みに関係なく却下 |
| G3 | 変更の根拠は北極星・成果指標・黒川さんの言葉だけ。器の指標は摩擦を減らす根拠にしかならない |
| G4 | 足す案より削る案を先に検討する |
| G5 | 1 PR で戻せる。古い書き出し JSON が読めなくなる変更は出さない。判定失敗は戻す |
| G6 | 4週ごとに「レッスン外の使用は増えたか」を問う。学習が増えて実戦が8週横ばいなら、機能でなく「場」を提案し、判断は黒川さんに仰ぐ |
| G7 | 停止条件。3サイクル変更なしで健全なら月次に落とす。12週で北極星が動かなければ前提を疑って報告する。レッスンが14日止まったら改善を止め、通知は1本だけ |
| G8 | 文字起こし・音声・メモ・キー・トレーナー名は同期しない。公開リポジトリに教材本文と個人データを入れない |
| G9 | ルーティン編集前に最新を読み updated_at を確認する。変更は全て PR 経由、merge は黒川さん。他のリポジトリには触れない |
| G10 | 罪悪感型の通知や失敗の演出を入れない。通知は週1＋月1 |
| G11 | 上方修正は §3 の規則でだけ行う。進行中の判定基準は動かさない |

反しないための仕組み（ラベルでなく物理分離）:
1. アプリの挙動を変える PR は、`docs/hypotheses/H-*.md` の追加か更新が無いと CI が落ちる（`scripts/hypothesis-gate.sh`）。
2. merge 権は人間（黒川さん）。ループは PR を出すまで。
3. 週次報告に G0〜G11 の自己監査表を必ず載せる。

保守（教材追加・バグ修正・依存更新）は変更回数に数えないが、PR と CI は通す。title を `fix:` `chore:` `data:` `docs:` `test:` `ci:` で始めるか、label `maintenance` を付ける。

## 5. 週次サイクル（日曜 19:00 JST）

1. **読む**: `improve-language-data/latest.json`（集計）、`docs/hypotheses/` の検証中の仮説、先週の報告。
2. **判定**: 判定日が来た仮説を、先に固定した基準で判定。残す／戻す（戻す＝revert PR）。
3. **診断**: 北極星・成果指標の動き、想定ペース比較、天井チェック（§3）、器の摩擦。足す前に削れるものを探す。
4. **決定**: 既定「変更なし」。変える場合は仮説ファイルを先に書き、1つだけ PR。
5. **実装と検証**: ブランチ → 実装 → `npm run check` と `npm test`（Playwright）→ PR。CI が緑でなければ PR を出さない。
6. **報告**: `improve-language-data/reports/YYYY-Www.md` に週次報告（今週のベスト1文・繰り返している詰まり1つ・来週の一点・ループの判断・自己監査表）を置き、PushNotification 1本。変更ゼロの週は「変更なし。理由」を書く。

## 6. データの所在とプライバシー

| データ | 場所 | 公開範囲 |
|---|---|---|
| 記録の本体（文字起こし・メモ・ピースの日本語） | 端末の localStorage、書き出し JSON | 本人のみ |
| 集計・ピースの英文と回数・サンプルの数値・実戦の1行 | `kuroyanyan/improve-language-data`（private） | 本人と週次ループ |
| カンペ（各レッスンの型・Key Phrases・See・Try・準備の質問・Act・追撃質問・注意。教材本文を含む） | `kuroyanyan/improve-language-data` の `kanpe/{rank}/NN.html`（private）。アプリが同期トークンで取得し端末に保存 | 本人のみ |
| アプリのコード・教材のトピック名と Key Phrases・仮説の定義と判定 | このリポジトリ（public） | 誰でも |
| API キー・同期トークン | 端末の localStorage `bizmates-log/keys`。書き出しに含めない | 本人のみ |

Bizmates の教材本文（HTML）は公開リポジトリに取り込まない。lessons.json に入れるのはトピック名と Key Phrases だけ。カンペ（See の原文を含む）は private のデータリポジトリにだけ置く。新しい Rank の教材が届いたら、教材 HTML → digest → カンペ生成 → `kanpe/{rank}/` へ追加、を保守（`data:`）として行う。
